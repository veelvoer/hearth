# hearth-desktop report (only what was run and seen)

Crate `hearth-desktop`, bin `hearth`, in the `rs` workspace. No webview. No commit made.

## Built
- `src/app.rs` state + controller core (state.json compatible with the Tauri app: same ~/.config/Hearth), notifications (notify-send / Windows toast crate), usage poll (30 s) with threshold alerts, SSE `/events` listener per computer (away mode when "ring me"), popups (permission, question, call, support, friend request) as `Event::Popup`, pending projects and pairing requests timers.
- `src/ctl.rs` every `cm.*` command of tauri `dispatch` as plain functions of `App`: settings, notes, stats, pair info/new code/requests/decide, hooks install/remove, accent/dark/palette (in `sys.rs`/`theme.rs`), setup paths, voice install/status/stt/tts, app icon, autostart, machines add/remove/discover, support start/verify/logout/call/state, relaunch, projects pending/accept/reject, guests/guests_set, share join, generic relay call, project move/continue, update run/check/later/status, hub status/phone code, upload (+ upload_path), open path/external, terminal open, pick folder/files (rfd), stop, send (hearth-client run stream), call action.
- `src/sys.rs` system colors (xdg portal via gdbus, KDE kdeglobals, Hyprland, GNOME gsettings, GTK css, Oxide `~/.config/oxide/theme.json`, Windows registry), autostart (.desktop / Run key), hooks, terminal, open. `src/color.rs` OKLab mixing + token derivation from a whole Oxide palette. `src/theme.rs` resolves settings + desktop into dark/surfaces/accent.
- `src/upd.rs` updater port (GitHub release, AppImage / deb / user AppImage / Windows installer / portable swap bat, sha256 + size check).
- `src/tray.rs` ksni (StatusNotifierItem over D-Bus, no GTK) on Linux, tray-icon on Windows. `src/single.rs` lock file + local port wake. `src/main.rs`: `mcp-ask`, `--version`, `--hidden`, embedded relay (same dir, CM_PORT), close-to-tray, relaunch.
- `src/ui.rs` + `ui/main.slint`: windows. Main window = `hearth_ui::App` (rs/ui) filled with real data by `src/screens.rs` (chats of all computers grouped Working now/Today/Yesterday..., history, usage tiles, computers, status, update card, dark/light + accent). Popups are own small frameless always-on-top Slint windows (`PopupWindow`). `HEARTH_UI=wiring` selects the old minimal wiring window. Dropped files (winit DroppedFile) upload.

## Verified (run, seen)
- `cargo test -p hearth-desktop`: 34 unit tests, `controller` integration test and `render` test pass (rerun after the last edit: all pass).
- Integration test against the in-process relay: embedded relay start; pair info/code; hooks into a temp HOME; usage -> state/history/notification; settings persistence; away listener; permission hook -> notification + popup -> allow answers the hook; question popup -> talk opens chat; notification suppressed when window in front; pairing request -> notification -> accept; chat run streams (session, deltas, end) via hearth-client; upload; add/remove computer; guests; support sign-in/logout against a fake server (bearer header seen); updater download with sha256/size checks against a fake server.
- Render test (software renderer, no display): rs/ui App with real rows, light + custom accent differs from dark and draws the accent, home/settings, popup. PNGs in ~/hearth-tmp/shots (looked at chats-light-accent.png and popup.png).
- Real release binary under a nested headless kwin (`kwin_wayland --virtual --socket wl-hearth`, test config XDG_CONFIG_HOME=~/hearth-tmp/cfg, HOME=~/hearth-tmp/home, CM_PORT=47699): starts, relay listens on 47699, second start exits in 29 ms (single instance), `--version` prints 1.40.0.
- Tray without a tray host (private dbus session): logs `no tray icon: ...StatusNotifierWatcher` and the app keeps running.

## Not done / blocked / untested
- **rs/ui's `App` only exposes the callback `new-chat()`** (rs/ui/REPORT.md "Public API"). The row open/pin/delete, composer send/stop, send-now, show-earlier, settings pick/toggle, onboarding finish/skip, pairing connect, permission prompt allow/deny, call hangup, update install/later callbacks live in sub-components and are not forwarded by `App`. So the real window is display-only (lists, tiles, devices, status, update card, theme) and cannot yet start a chat or answer from the UI. The controller functions for all of those exist and are tested (`send`, `call_action`, `update_run`, `pair_decide`, `add_machine`, ...); wiring them needs `App` to forward those callbacks and expose the open chat's `messages`. rs/ui also keeps its demo messages unless cleared (I clear them) and draws chat rows dark in light mode with my rows (seen in chats-light-accent.png; possibly `selected`/swiped defaults, not investigated).
- rs/ui `Palette` only takes `dark` and `accent-override`; the desktop's whole Oxide palette is parsed and turned into tokens (`color.rs`, tested) but can only paint the wiring window and popups until Palette exposes in-properties.
- Popups: Slint/winit cannot set always-on-top or position on Wayland (compositor decides); skip-taskbar not available. Not seen on a real compositor.
- Not run: tray with a real host (menu, ring toggle), notify-send delivery, Windows build/registry/toast/tray (code written, not compiled for Windows), rfd dialogs, drag-drop of a real file, project move/continue (needs a server relay; only unit-level helpers tested), voice install/stt/tts, hub status, share join, updater end to end (only the download+verify part), autostart on a real session, terminal open, system accent/dark from a real portal, the Oxide file against the user's real theme.
- Binary is 5 MB larger than the Tauri binary (but needs no WebKitGTK).

## Update: rs/ui root App fully wired (test run, passing)
- `src/wire.rs` binds every callback of rs/ui's root `App` to the controller and pours controller events into its properties: chats/history (grouped, pinned, tags, search, project filter), the open chat's messages (relay history as markdown rows, live run records appended, queued follow-ups, working row), send/stop/send-now/remove-queued/show-earlier, composer pills (mode/model/effort go to the relay with the message), pin/rename (name taken from the search box, because rs/ui has no text prompt)/delete, usage numbers + tiles (+range), settings switches -> settings keys, theme, devices add/remove/refresh, update card, permission sheet (used when the window is in front, otherwise the separate popup window), pairing by `host code` or hearth:// link, onboarding (shown while `onboarded` is unset), and the Oxide/system palette written into every `Palette` token (the own dark/light values are restored when the desktop gives none).
- Test `tests/wire.rs` (headless, real relay with a stub claude): fires the root callbacks and checks the effect: onboarding finish saved; chats from relay; open chat shows history; send resumes `--resume seed1` and streams the answer into `messages`; a follow-up is queued, Stop ends the run, the queued one then runs; remove-queued; pin and rename stored in the relay's chat-tags; search filter; setting toggles and theme persisted; new chat in a folder with the chosen mode reaching the relay (`--permission-mode plan`); delete removes the session; a permission hook shows the sheet and `prompt-answered("deny")` answers the hook with deny; pair-connect adds a computer, device-remove removes it; the Oxide palette lands in `Palette` and is undone.
